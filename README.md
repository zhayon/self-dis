# self-dis

Закрытый чат с голосовыми комнатами для одной небольшой общины. Сервер написан на Rust и рассчитан на Linux. Страница открывается в браузере, отдельную сборку клиента запускать не нужно.

Обычно здесь 5–10 человек. Регистрации нет: администратор сам выдаёт имя и пароль. Ролей две, администратор и участник. Личных сообщений, ботов, видео и демонстрации экрана нет.

## Что есть сейчас

- Один текстовый канал. При первом запуске он называется «общий». Его можно переименовать, удалить нельзя.
- Несколько голосовых комнат. Их создаёт, переименовывает и удаляет администратор, из браузера или из командной строки.
- Голос через WebRTC. Сервер пересылает звук остальным в той же комнате и не смешивает его.
- Список тех, кто сейчас подключён.

Состав голосовой комнаты живёт в памяти. После перезапуска сервера чат остаётся, а из голоса все выходят.

## Запуск

Нужен стабильный Rust. Из корня репозитория:

```shell
cargo run -p self-dis-server --bin self-dis -- --data data user add \
  --username ada --password password123 --role admin
cargo run -p self-dis-server --bin self-dis -- --data data serve
```

База SQLite появится в каталоге `data`. Пароль от 8 до 128 символов. Имя от 2 до 32 символов: начинается с буквы или цифры, дальше ещё буквы, цифры, точка, `_` и `-`. Если `--password` не передан, программа спросит его в терминале и не покажет на экране.

После запуска откройте http://127.0.0.1:8080. Участника без прав на комнаты добавляют так:

```shell
cargo run -p self-dis-server --bin self-dis -- --data data user add \
  --username bob --password password123 --role member
```

Полезные команды: `user list`, `channel list`, `channel add-voice --name болталка`, `channel rename <id> --name новое`, `channel delete <id>`. Изменение канала из командной строки подключенные браузеры увидят после переподключения. То же действие из браузера приходит всем сразу.

Другой адрес HTTP задаётся флагом `--listen`, например `0.0.0.0:8080`.

## Виртуалка Ubuntu

На сервер не нужно ставить Rust. Туда копируется один бинарь, его поднимает systemd и слушает все интерфейсы, не только localhost. База лежит в `/var/lib/self-dis`. Повторный запуск скрипта заменяет бинарь и перезапускает сервис, файл `/etc/self-dis.env` при этом не трогает.

Собрать Linux-бинарь с этого Mac можно так. Первый раз на Apple Silicon это долго: сборка идёт для `linux/amd64` внутри Docker. Нужен запущенный Docker.

```shell
scripts/build-linux.sh
```

Для виртуалки ARM64: `PLATFORM=linux/arm64 scripts/build-linux.sh`.

Тот же бинарь собирает GitHub Actions на Ubuntu при пуше в `main` и по ручному запуску workflow `Linux binary`. Готовый файл лежит в артефакте `self-dis-linux-amd64`. Этот путь быстрее, если Docker на маке занят эмуляцией.

Дальше, с машины, где настроен SSH к виртуалке:

```shell
RTC_IP=203.0.113.10 scripts/deploy.sh ubuntu@203.0.113.10 dist/self-dis
```

`RTC_IP` — адрес, который браузер подставляет в голос. Если флаг не задан при первой установке, скрипт берёт адрес самого сервера. Когда он серый (`10.`, `192.168.` или `172.16–31`), для голоса из интернета его нужно поправить в `/etc/self-dis.env` и выполнить `sudo systemctl restart self-dis`. Пользователь SSH должен иметь возможность `sudo`.

Откройте на файрволе TCP `8080` и UDP `9000`. Страница будет на `http://<адрес>:8080`. Логи: `sudo journalctl -u self-dis -f`. Первого администратора создают на сервере. Команду можно запускать от root: программа сама перейдёт к владельцу каталога базы.

```shell
/usr/local/bin/self-dis --data /var/lib/self-dis user add \
  --username ada --generate-password --role admin
```

Пароль будет напечатан один раз. Для участника уберите `--role admin`. Если пароль забыт, человека не удаляют: старый вход перестаёт работать, имя и сообщения остаются.

```shell
/usr/local/bin/self-dis --data /var/lib/self-dis user passwd \
  --username ada --generate-password
```

Чат с другой машины по голому HTTP уже открывается. Микрофон браузер даст только если страница открыта по HTTPS. Для этого перед сервисом ставят Caddy и домен, а в `/etc/self-dis.env` оставляют `LISTEN=127.0.0.1:8080`, UDP по-прежнему наружу:

```
example.com {
    reverse_proxy 127.0.0.1:8080
}
```

UDP `9000` через этот HTTP-прокси не пойдёт, порт должен быть открыт до процесса напрямую.

## Голос не на своём компьютере

На `localhost` микрофон доступен и без HTTPS. Если страницу открывают с другой машины, сайт должен быть на HTTPS, иначе браузер не даст микрофон. Звук идёт отдельным UDP, его не протащить через HTTP-прокси: порт должен быть открыт прямо до процесса.

По умолчанию голосовой сокет — `0.0.0.0:9000`. В браузер подставляется `127.0.0.1`, когда HTTP слушает локальный или неопределённый адрес. Для сервера в сети укажите адрес, который видит браузер:

```shell
cargo run -p self-dis-server --bin self-dis -- --data data serve \
  --listen 0.0.0.0:8080 \
  --rtc-udp 0.0.0.0:9000 \
  --rtc-ip 203.0.113.10
```

Своего TURN-сервера нет. На localhost клиент не использует STUN. С другого адреса он спрашивает `stun.l.google.com`. Проверять голос лучше в Chrome: Firefox может не принять кандидат `127.0.0.1`.

## Разработка

```shell
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Контракт сообщений лежит в `crates/protocol`. Его же сможет использовать будущий клиент на Rust для macOS и Windows. Сервер и страница — в `crates/server`. Страница — обычные `index.html`, `app.css` и `app.js` в `crates/server/static`.

Заметки, по которым агенту проще продолжить работу, лежат в `AGENTS.md`.
