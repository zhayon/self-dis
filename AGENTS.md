# self-dis

Закрытый аналог Discord на одну общину: текстовый чат и несколько голосовых комнат. Сервер только под Linux, на Rust. Первый клиент — браузер без сборщика. Протокол общий, чтобы позже сесть на него нативному клиенту macOS/Windows.

Пользователь пишет по-русски. Строки интерфейса, CLI и ошибок протокола — русские. Идентификаторы в коде — английские.

## Уже решено

Не переоткрывать без явной просьбы:

- Один процесс, обычно 5–10 человек, одна община на развёртывание. Нет гильдий, личных сообщений, ботов, федерации и E2EE.
- Роли только `admin` и `member`. Открытой регистрации нет: админ выдаёт имя и пароль. Комнаты и пользователей ведёт админ. Участник пишет в чат и входит в голос.
- В первой версии один текстовый канал. Миграция создаёт его с именем «общий», если текстовых каналов нет. Удалять текстовый канал нельзя, переименовать можно. Голосовых комнат несколько.
- База SQLite. Состав голосовых комнат только в памяти: перезапуск роняет голос, чат остаётся.
- Голос — WebRTC SFU на `str0m`. Сервер пересылает Opus и не смешивает. Одно `RTCPeerConnection` на участника. Видеодорожки отличаем и пока отвергаем. TURN нет.
- HTTP-токен только заголовком `Authorization: Bearer`. Браузерный WebSocket его не ставит, поэтому первый кадр — `auth`.
- Нативный клиент не писать, пока его явно не попросили. Видео и демонстрацию экрана не добавлять в этот этап.

## Карта

- `crates/protocol` — JSON-контракт версии `PROTOCOL_VERSION` (сейчас 1). Внутри `serde` с тегом `type` в `snake_case`. Неизвестное поле игнорируется, неизвестный `type` — ошибка. Идентификаторы — числа в безопасном диапазоне JavaScript. Время — RFC 3339 UTC.
- `crates/server` — библиотека `self_dis_server` и бинарник `self-dis`.
  - `src/db.rs`, `migrations/` — пользователи, сессии, каналы, сообщения.
  - `src/http.rs` — REST и страница. Файлы из `static/` вшиты в бинарь. Если каталог исходников на месте, берётся он, чтобы править JS без пересборки. На сервере каталога нет, отдаётся вшитая копия.
  - `src/ws.rs` — сокет: первое сообщение `auth`, присутствие, рассылка.
  - `src/voice.rs` — поток SFU. Запускается только из `serve`.
  - `src/state.rs` — база, рассылка, присутствие, `Voice`.
  - `static/` — `index.html`, `app.css`, `app.js`. Отдельной сборки нет, `cargo run` достаточно.
  - `tests/api.rs` — сквозные тесты.
- `data/` и `*.db` в git не входят.
- `deploy/self-dis.service`, `scripts/build-linux.sh`, `scripts/deploy.sh` — выкладка одного Linux-бинаря на Ubuntu. На виртуалке нет Rust. Слушать нужно `0.0.0.0`, в `--rtc-ip` писать адрес, который видит браузер.

Команды CLI `channel` пишут базу и не рассылают событие. Подключённый клиент видит такое изменение после переподключения. Изменения из WebSocket рассылаются сразу, включая отправителя.

## Команды

```shell
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p self-dis-server --bin self-dis -- --data data user add --username ada --password password123 --role admin
cargo run -p self-dis-server --bin self-dis -- --data data serve
```

`serve` по умолчанию слушает `127.0.0.1:8080` и UDP `0.0.0.0:9000`. Если HTTP-адрес не задан явно как конкретный IP, в ICE объявляется `127.0.0.1`. Для VPS: `--listen 0.0.0.0:8080 --rtc-ip <публичный IP>`. Страница на чужой машине должна открываться по HTTPS, иначе браузер не даст микрофон. UDP должен доходить до процесса напрямую, HTTP-прокси его не протащит. `localhost` — безопасный контекст, TURN не нужен; не на localhost клиент добавляет `stun:stun.l.google.com:19302`.

В debug-профиле у `argon2` и `blake2` стоит `opt-level = 3`, иначе хеш пароля считается секундами. Не убирать.

## Протокол голоса

Клиент шлёт `join_voice`, затем первым SDP-кадром `rtc_offer`. Сервер отвечает `rtc_answer`. Обе стороны шлют `rtc_ice`. Когда сервер добавляет или убирает дорожку, он шлёт `rtc_offer`, клиент отвечает `rtc_answer`. `voice_state` — полный снимок комнаты, клиент заменяет им прежний список этой комнаты. `ready.voice` — снимок всех комнат на момент подключения.

Коды ошибок: `invalid_credentials`, `unauthenticated`, `forbidden`, `not_found`, `invalid`, `voice_not_ready`, `internal`. Подробности `internal` пишутся в лог, клиент видит «внутренняя ошибка». `voice_not_ready` остаётся верным ответом, если сокет голоса не запущен: так устроены CLI и тест `login_chat_and_voice_rooms`.

## Голосовой цикл

`str0m` после каждой правки одного `Rtc` нужно вычитать через `poll_output` до `Output::Timeout`, и только потом снова менять этот же `Rtc`. Разные соединения можно трогать по очереди. Порядок в `voice.rs`: выбросить умершие соединения, вычитать всех в очередь, переслать одно событие, иначе применить один отложенный ICE-кандидат, иначе взять одну команду, иначе читать UDP не дольше 20 мс и разослать `Input::Timeout`.

Сокет слушает `0.0.0.0`, а в SDP объявлен `--rtc-ip`. В `Input::Receive` адресом назначения должен быть объявленный IP, не `0.0.0.0`: иначе ICE выбрасывает STUN и браузер навсегда остаётся в «соединяюсь».

Криптографию ставить один раз: `str0m::crypto::from_feature_flags().install_process_default()`. Соединение ICE-lite, наружу объявляется host-кандидат. Пакеты чужой комнаты не пересылать. `muted` выбрасывает звук, но человек остаётся в снимке. Ответ SDP и ошибка этого соединения идут в сокет, который его поднял (`signal_id`), а не во всю рассылку. При обрыве сокета голос покидает только тот сокет, который входил.

Ориентир по циклу и состояниям дорожки — пример `str0m` `examples/chat.rs`, но SDP у нас едет по уже существующему WebSocket, а не по data channel. Аудио без ключевых кадров.

## Браузер

Ключ сессии `localStorage`: `self-dis-token`. Не `sessionStorage`: Safari на iOS стирает его при закрытии браузера. Сервер помнит токен 30 дней. Имена и текст сообщений только через `textContent`. Повтор `message.id` пропускать: история и живой кадр пересекаются. Канал и пользователя с тем же id обновлять. `protocol !== 1` показывать как ошибку. Enter отправляет, Shift+Enter переносит строку. Обрыв WebSocket переподключает через секунду и сам в голос не возвращает. Если в `voice_state` своей комнаты больше нет текущего пользователя, локальный звонок завершить. `getUserMedia` с `video: false`. Отказ микрофона — `leave_voice` и текст «нет доступа к микрофону».

Свои ICE копить, пока ушёл offer. Чужие ICE копить, пока не установлен `remoteDescription`. Первичный offer создаёт клиент. Следующий offer приходит от сервера. `onnegotiationneeded` не использовать. Firefox может отвергнуть кандидат `127.0.0.1`; проверять голос в Chrome на localhost.

## Проверка

После правок Rust: `cargo fmt`, clippy с `-D warnings`, `cargo test --workspace`. Тест без `start_voice` по-прежнему ждёт `voice_not_ready`. Тест со `start_voice` на `127.0.0.1:0` ждёт `voice_state`.

После правок страницы пройти сценарий в браузере: вход, сообщение, перезагрузка с тем же токеном, создание комнаты админом, отказ микрофона, второе окно другого пользователя видит присутствие и живое сообщение. Снимок экрана без этих действий проверкой не считается.

## Чего не делать

- Не коммитить и не пушить, пока не попросили. Git config не менять. Секреты, `data/` и базы не добавлять.
- Не ломать JSON-теги и смысл кадров версии 1. Новое поле можно добавить как игнорируемое старым клиентом. Несовместимое изменение — новая `PROTOCOL_VERSION`.
- Не декодировать и не смешивать звук на сервере.
- Не прятать голос за приёмами, которые есть только в браузере: кадры должен понимать будущий Rust-клиент.
